# S1防误伤修正

单文件 Tampermonkey 脚本。按用户自己维护的名单，在发送前于词内插入 U+200C（零宽非连接符）。

[安装脚本](https://raw.githubusercontent.com/mirari/s1-userscript/main/s1-keyword-zwnj.user.js)

## 名单管理

脚本不包含任何内置名单，新安装时为空。

通过篡改猴菜单打开「管理误伤修正名单」：

- 手动添加、修改、删除，每行一个词，至少两个字符。
- 点击「保存」自动去重，去除空行、首尾空白和 U+200C，忽略单字符；区分大小写，保留首次出现顺序。
- 可以保存空名单；取消或按 Esc 放弃本次编辑。
- 已打开的标签页自动同步设置；有未保存草稿时保留草稿，并提示其他页面的变更。
- 设置页跟随系统深色模式。名单可直接在文本框中手动复制、粘贴，无专用剪贴板功能或权限。

名单和开关保存在本地。正文处理不联网，不上传内容。

## Gist 同步

在设置页展开「Gist 同步」。使用 GitHub personal access token：fine-grained token 需要用户级 Gists 读写权限，classic token 需要 `gist` scope。

- 第一台设备：填令牌，Gist ID 留空，点击「上传当前名单」创建 Secret Gist。保留返回的 Gist ID，再点击保存。
- 其他设备：填有权限的令牌和相同的 Gist ID，点击「拉取名单」，检查后保存。
- 上传使用当前编辑框的名单和启用状态；拉取只更新草稿，点击保存后生效。普通保存不会自动联网。
- 连接设置在同步操作或保存时保存在本机；令牌不上传到同步文件。清空令牌后保存可移除本机凭据。
- 云端使用独立文件 `s1-anti-misfilter.json`，不会修改 S1 Plus 的文件。
- 覆盖云端前需要确认，并再次读取检查变化。Gist API 的读取与写入不是原子事务，仍应避免两台设备同时上传。
- Secret Gist 不会列在公开列表中，但不是加密存储，知道链接的人可以读取；Gist 也会保留历史版本。

同步仅发送名单和启用状态，不发送帖子内容。网络失败保留本地数据；创建请求超时时请先在 GitHub 检查是否已创建，避免重复创建。

实现参考了 S1 Plus 的连接信息隔离、同步基线与上传前版本检查思路。API 依据 [GitHub Gists 文档](https://docs.github.com/en/rest/gists/gists)。

## 安装和更新

安装 Tampermonkey 后打开上方链接安装，刷新 S1 页面。交付文件只有 `s1-keyword-zwnj.user.js`。

脚本包含固定的 `@updateURL` 和 `@downloadURL`；维护者发布新版本时递增 `@version`，Tampermonkey 按用户更新设置检查并下载新版。脚本更新不覆盖已经保存的自定义名单，也不会注入词条。

若已安装本地试作版，请从安装链接手动安装当前正式版，以确保版本和更新地址一致。

## 支持范围

适用于 S1 的标准 Discuz 编辑框、e_iframe 富文本框、常见发送按钮、submit 事件和 Ctrl/Cmd+Enter。可使用「立即处理当前内容（不发送）」先检查效果。实际插入字符后显示约 2.5 秒的「已自动处理X个词汇以防误伤」提示（X 为本次实际处理的不同词汇数量，同一词重复出现只计一次）；未匹配或已处理过的内容不提示。提示不阻塞发送，整页跳转时会随当前页面消失。

插入字符可能影响链接与代码的使用；论坛若清除零宽字符或使用其他过滤策略，处理可能无效。不同编辑器或直接调用提交接口的页面可能需要适配。

本地验证覆盖空名单、保存去重、跨标签页同步、草稿保留、关闭设置及匹配幂等性；尚未实际发帖验证。
